Build on the gates.

The Kiln public API exposes workspace projects, generated artifacts and workstream runs. Every key is scoped, every webhook is signed, and every production action still requires a human approval in the console.

API version v1 · Base URL https://kiln-kohl.vercel.app · Status /api/status

Create an API key

Sign in, open Developer, and create a key. The raw key is shown once. Keys require a paid workspace and support these scopes:

projects:readList projects, read a project workspace and list artifacts.
runs:writeRun a single workstream and create a new artifact revision.
projects:writeReserved for project mutation endpoints.
webhooks:readReserved for webhook metadata endpoints.
curl https://kiln-kohl.vercel.app/api/v1/projects \
  -H "Authorization: Bearer kiln_live_..."

Response shape

{
  "ok": true,
  "data": { "id": "art_...", "functionKey": "architecture", "revision": 2 },
  "meta": { "version": "v1", "usage": { "used": 18200, "quota": 1200000 } }
}

Errors use { "ok": false, "error": "message", "code": "OPTIONAL_CODE" } with conventional HTTP status codes. Quota, plan and role failures return 402 or 403 with an actionable code.

Signed webhooks

Create a webhook in Developer. Kiln sends JSON with an x-kiln-event header and an HMAC-SHA256 signature in x-kiln-signature-256. Verify the raw request body before parsing it.

const crypto = require('crypto');

function verify(rawBody, header, secret) {
  const expected = 'sha256=' + crypto
    .createHmac('sha256', secret)
    .update(rawBody)
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(header || '')
  );
}

Events include project.created, artifact.generated, deployment.created, deployment.approved, billing.plan.activated, comment.created, member.invited and backup.created. Failed deliveries retry with exponential backoff through the durable job queue.

Webhook URLs must be HTTPS and cannot target private, loopback, link-local or internal hosts. Delivery records are retained for troubleshooting.

SCIM provisioning

Owners and admins on a paid workspace can issue a SCIM bearer token from Security. The endpoint is compatible with SCIM 2.0 Users, Groups and ServiceProviderConfig:

GET  /api/scim/v2/Users?filter=userName eq "person@example.com"
POST /api/scim/v2/Users
PATCH /api/scim/v2/Users/:id
DELETE /api/scim/v2/Users/:id
GET  /api/scim/v2/Groups
GET  /api/scim/v2/ServiceProviderConfig

Groups map to workspace roles: admin, member and viewer. The workspace owner cannot be modified through SCIM. Send Authorization: Bearer kiln_scim_... and Content-Type: application/scim+json.

Operational notes

  • Keys are hashed at rest and can be revoked immediately.
  • Requests are rate-limited. A 429 response is safe to retry with backoff.
  • Public API runs consume workspace tokens and obey the same plan and role checks as the console.
  • Scheduled jobs run through POST /api/internal/jobs/run with the deployment’s cron secret.
